# License Policy

**Effective Date:** 2026-01-06

This document defines the open source license compliance policy for Itqahn.

---

## Overview

Itqahn uses open source software and requires all dependencies to comply with approved licenses.

---

## Approved Licenses

### Permissive Licenses (Allowed)

These licenses are approved for use in all contexts:

| License | SPDX ID |
|---------|---------|
| MIT License | MIT |
| Apache License 2.0 | Apache-2.0 |
| BSD 2-Clause | BSD-2-Clause |
| BSD 3-Clause | BSD-3-Clause |
| ISC License | ISC |
| CC0 1.0 | CC0-1.0 |
| Unlicense | Unlicense |

### Weak Copyleft (Conditional)

These licenses are allowed with conditions:

| License | SPDX ID | Condition |
|---------|---------|-----------|
| LGPL 2.1 | LGPL-2.1 | Dynamic linking only |
| LGPL 3.0 | LGPL-3.0 | Dynamic linking only |
| MPL 2.0 | MPL-2.0 | File-level copyleft |
| EPL 2.0 | EPL-2.0 | Module-level copyleft |

### Strong Copyleft (Restricted)

These licenses require legal review:

| License | SPDX ID | Restriction |
|---------|---------|-------------|
| GPL 2.0 | GPL-2.0 | Not in proprietary code |
| GPL 3.0 | GPL-3.0 | Not in proprietary code |
| AGPL 3.0 | AGPL-3.0 | Not in any Itqahn code |

### Prohibited Licenses

These licenses are NOT allowed:

| License | Reason |
|---------|--------|
| SSPL | Non-OSI, restrictive |
| Commons Clause | Commercial restriction |
| Elastic License | Commercial restriction |
| BSL | Time-delayed open source |
| Proprietary | Requires separate agreement |

## Compliance Process

### Dependency Addition

Before adding a new dependency:

1. **Identify license** — Check package metadata
2. **Verify approval** — Confirm license is approved
3. **Document** — Record in dependency manifest
4. **Review** — Security scan for vulnerabilities

### Automated Checks

License compliance is enforced via CI:

```yaml
# CI pipeline
- name: License Check
  run: |
    licensee detect
    npx license-checker --onlyAllow "MIT;Apache-2.0;BSD-2-Clause;BSD-3-Clause;ISC"
```

### SBOM Requirements

All releases must include SBOM with license information:

```json
{
  "components": [
    {
      "name": "express",
      "version": "4.18.2",
      "licenses": [
        {
          "license": {
            "id": "MIT"
          }
        }
      ]
    }
  ]
}
```

## Exception Process

For licenses not on the approved list:

1. **Request exception** — File request with justification
2. **Legal review** — General Counsel evaluates
3. **Risk assessment** — Security team reviews
4. **Decision** — Approve, deny, or require conditions
5. **Document** — Record decision in exception log

### Exception Request Template

```markdown
## License Exception Request

**Dependency:** [name]
**Version:** [version]
**License:** [license]
**Repository:** [URL]

### Justification
[Why is this dependency needed?]

### Alternatives Considered
[What alternatives were evaluated?]

### Risk Mitigation
[How will compliance risks be managed?]
```

## Agents and License Compliance

### Agent Responsibilities

The **License Compliance Officer** agent:
- Scans dependencies for license compliance
- Flags prohibited licenses
- Generates attribution notices
- Reports compliance status

### Enforcement

License violations:
- Block PR if prohibited license detected
- Warn on conditional licenses
- Require exception for restricted licenses

## Third-Party Code

### Vendored Code

When vendoring third-party code:
- Preserve original license file
- Document in NOTICE
- Do not modify license headers

### Code Snippets

When using code snippets from:
- Stack Overflow (CC BY-SA) — Attribute in comments
- GitHub (check license) — Verify compatibility
- Documentation (usually permissive) — Attribute source

## Outbound Licensing

### Itqahn Source Code

Itqahn proprietary code is:
- Not open source
- Licensed to customers via service agreement
- Protected by intellectual property laws

### Customer Output

Code generated by Itqahn for customers:
- Owned by the customer
- No license restrictions from Itqahn
- Customer responsible for their use
